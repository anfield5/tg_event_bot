# Команда: `/shareevent [target] [флаги...]`

**Уникальные флаги:** `-mgl`, `-sngl`, `-swl` (описаны здесь)
**Переиспользуемый флаг:** [`-clc`](../flags/clc_clickability.md) (здесь работает как **per-share override**, не как настройка всего события)

---

## Назначение

Пересылает синхронизированную версию активного события в дочернюю группу/канал. Все сообщения об ошибках уходят обратно в главный хаб (даже если сама ошибка произошла при обращении к целевому чату) — админ никогда не должен смотреть в целевой чат, чтобы понять, что пошло не так.

## Полный порядок проверок (важен — при первой же неудаче всё останавливается)

1. **Синтаксис** — должен быть хотя бы один аргумент (target). Иначе — ошибка с полным списком флагов.
2. **Гейтинг `-clc`** — если передан `-clc`/`-clickability`, но у хаба нет фичи `clickability` → ошибка, **вся команда** прерывается (даже если остальные флаги валидны).
3. **Активное событие** — должно существовать (`event_status IN (0, 1)`) в чате, откуда вызвана команда. Иначе — "No active event found for this group".
4. **Проверка заполненности по `-limit`** — если у события задан `-limit`, и текущий headcount (хаб + все существующие шаринги) уже **достиг или превысил** лимит → шаринг блокируется целиком, новую группу/канал добавить нельзя, пока не освободится место.
5. **Резолв target** — сначала ищется как alias (через `/setalias`) для этого хаба; если не найден — используется буквально как chat_id.
6. **Нельзя шарить в себя же** — если resolved target совпадает с самим хабом → ошибка.
7. **Лимит на количество шарингов** (`get_feature_limit_for_chat(..., "shareevent")`) — если для этой пары (хаб → target) уже достигнуто максимальное число шарингов, разрешённое тарифом → ошибка с указанием лимита. `None` = безлимитно.
8. **Уже расшарено?** — если для этого события в этот target уже есть запись в `event_shares` → ошибка "already been added", повторно шарить нельзя (нужно сначала убрать через отдельный механизм, если такой предусмотрен).
9. **Валидность target как chat** — `get_chat()` к целевому чату. Не найден / бот не участник → ошибка "Chat not found or bot is not a member".
10. **Бот — админ в target?** — если бот не состоит в чате или не админ → отдельные разные сообщения ("add and promote" vs "please promote").
11. **Анонимность вызывающего** — если команда вызвана от имени "Group Anonymous Bot" (аноним-режим) → отдельная ошибка с просьбой отключить анонимность (админский статус нельзя проверить анонимно).
12. **Вызывающий — админ в target?** — проверяется **личное** членство и админ-статус именно вызвавшего команду человека в целевом чате, не только бота. Не участник / не админ → соответствующая ошибка.
13. Если все проверки пройдены — отправляется placeholder-сообщение в target, создаётся запись в `event_shares`, отправляется подтверждение в хаб, запускается полный рендер (`schedule_view_refresh`).

## Уникальные флаги

**`-mgl` / `-maingoinglist visible|hidden|onlycount`**
— Видимость списка Going **именно в этом расшаренном посте**. Дефолт — `onlycount` (единственный флаг в этой команде, где дефолт **не** `visible`, в отличие от `-wl`/`-ngl` в других командах).

**`-sngl` / `-sharenotgoinglist visible|hidden|onlycount`**
— Override видимости Not Going **для этого конкретного шаринга**. Не указан → наследует значение `-ngl` самого события.

**`-swl` / `-sharewaitlist visible|hidden|onlycount`**
— Override видимости Waitlist **для этого конкретного шаринга**. Не указан → наследует значение `-wl` события.

**`-clc` / `-clickability on|off`** — см. [общий спек флага](../flags/clc_clickability.md). Здесь — override для конкретного чата, не всего события.

## Порядок аргументов

Флаги и target **можно указывать в любом порядке** — парсер сначала вычленяет все распознанные флаги, первый оставшийся "свободный" токен становится target. Пример: `/shareevent -mgl visible @mychannel` работает так же, как `/shareevent @mychannel -mgl visible`.

## Alias vs числовой chat_id

Target может быть:
- **Alias** (настроен через `/setalias` для этого хаба) — резолвится в реальный chat_id перед всеми дальнейшими проверками.
- **Числовой chat_id напрямую** (`-1001234567890`) — используется как есть.
- **`@username`** — передаётся в `get_chat()` как есть; Telegram сам резолвит.

## Тест-сценарии

- [ ] **S1 — Синтаксис.** `/shareevent` без аргументов → ошибка с подсказкой по флагам.
- [ ] **S2 — Дефолт `-mgl`.** `/shareevent -200` без `-mgl` → `share_mode = '-onlycount'`.
- [ ] **S3 — Гейтинг `-clc` на FREE.** FREE-хаб, `/shareevent -200 -clc off` → ошибка, **весь** шаринг не создаётся (даже если остальное валидно).
- [ ] **S4 — Нет активного события.** Хаб без события → "No active event found for this group".
- [ ] **S5 — Блокировка по заполненности.** Событие с `-limit 10`, headcount уже 10 → `/shareevent` **любого** нового target блокируется полностью.
- [ ] **S6 — Шаринг в себя.** `/shareevent` с target = сам хаб → ошибка "Cannot share an event to the same group that owns it".
- [ ] **S7 — Повторный шаринг.** Тот же event_id + тот же target уже есть в `event_shares` → ошибка "already been added", вторая запись не создаётся.
- [ ] **S8 — Лимит по количеству шарингов.** Тариф ограничивает 2 шаринга на target, уже есть 2 → 3-й отклоняется с сообщением о лимите.
- [ ] **S9 — Бот не админ в target.** `get_chat_member` для бота возвращает `member` (не admin/creator) → "Bot is in the chat but not an admin", запись не создаётся.
- [ ] **S10 — Аноним-режим вызывающего.** `user_id == GROUP_ANONYMOUS_BOT_ID` → отдельная ошибка про отключение анонимности, дальнейшие проверки не выполняются.
- [ ] **S11 — Вызывающий не админ в target.** Бот — админ, но сам вызывающий — обычный участник target → "You need admin rights in the target chat to share there".
- [ ] **S12 — Резолв alias.** Target задан как настроенный alias → корректно резолвится в реальный chat_id **до** всех последующих проверок (включая "шаринг в себя").
- [ ] **S13 — Порядок флагов не важен.** `/shareevent -sngl hidden @channel -mgl visible` и `/shareevent @channel -mgl visible -sngl hidden` дают идентичный результат.
- [ ] **S14 — Успешный шаринг.** Все проверки пройдены → в target приходит placeholder-сообщение, в хаб — подтверждение с именем/alias цели, `event_shares` содержит новую строку со всеми override-полями.
- [ ] **S15 — Override без наследования путается.** Событие с `-ngl hidden`, шаринг с `-sngl visible` → **этот** дочерний чат показывает Not Going, несмотря на `hidden` у события в целом.
