# Команды: `/newevent` и `/editevent`

Обе команды используют **общий парсер** (`parse_event_args`) и одинаковую логику валидации флагов — поэтому описаны в одном файле. Различия отмечены явно в каждом разделе.

**Общие флаги:** `-d`/`-gi`/`-ni`/`-limit` (описаны здесь, уникальны для этой пары команд)
**Переиспользуемые флаги:** [`-wl`](../flags/wl_waitlist.md), [`-ngl`](../flags/ngl_notgoinglist.md), [`-clc`](../flags/clc_clickability.md)

---

## `/newevent [название] [флаги...]`

### Назначение
Создаёт новое событие Going/Not Going в текущем чате.

### Поведение
1. Название события — обязательный аргумент. Без него → ошибка синтаксиса, событие не создаётся.
2. Если в чате уже есть активное событие (`event_status IN (0, 1)`) — новое всё равно создаётся, но пользователю показывается предупреждение: старый пост остаётся кликабельным для участников, но команды `/waitlist`/`/editevent` переключаются на **новое** событие.
3. При наличии PRO и настроенного Google Sheet — строка добавляется во вкладку `Events` (`EVENT_ID, EVENT_NAME, CREATED_AT, CREATED_BY, EVENT_DATE, CLOSED_AT, STATUS, AMOUNT`), статус `OPEN`, `AMOUNT = 0`.
4. Если PRO, но Sheet **не настроен** — отдельное сообщение "Please specify google sheet for save" (событие при этом всё равно создаётся успешно).
5. FREE-хаб — ничего не пишется в Sheets, без ошибок и предупреждений (тихо по дизайну).

### Уникальные флаги

**`-d` / `-date <dd.mm.yyyy> [HH:MM]`**
— Дата события, время опционально. Невалидный формат → ошибка, событие не создаётся.

**`-gi` / `-goingicon <эмодзи>`**
— Кастомная иконка для кнопки/списка Going. Без флага — дефолтная иконка проекта.

**`-ni` / `-notgoingicon <эмодзи>`**
— Кастомная иконка для Not Going. Без флага — дефолтная.

**`-limit <N>`**
— Лимит суммарного числа участников (going + гости), считая главный хаб и все шаринги вместе. Требует PRO (фича `event_limit`). Не указан → лимита нет (безлимитно).

### Тест-сценарии `/newevent`

- [ ] **N1.** `/newevent` без названия → ошибка синтаксиса, ничего не создаётся.
- [ ] **N2.** `/newevent Party` → создаётся с дефолтными иконками, без даты, без лимита.
- [ ] **N3.** `/newevent Party -gi 🎉 -ni 😢` → иконки применяются в посте.
- [ ] **N4.** `/newevent Party -d 32.13.2026` (невалидная дата) → ошибка, событие не создаётся.
- [ ] **N5.** `/newevent Party -limit 20` на FREE-хабе → ошибка тарифа, событие не создаётся вообще (не только лимит игнорируется — вся команда отклоняется).
- [ ] **N6.** Второй `/newevent` при уже активном первом → оба существуют, предупреждение показано, `/editevent` теперь адресует новый.
- [ ] **N7.** PRO-хаб без настроенного Sheet → событие создаётся, отдельным сообщением приходит "Please specify google sheet for save".

## `/editevent [название] [флаги...]`

### Назначение
Редактирует активное событие текущего чата. Обновляются **только явно переданные** поля — остальные сохраняют текущее значение.

### Поведение
1. Без активного события (`event_status IN (0, 1)`) → ошибка "No active event found to edit".
2. Без единого аргумента → ошибка синтаксиса.
3. **`-d`/`-gi`/`-ni`** — если явно не переданы, старое значение сохраняется без изменений.

### Особая логика `-limit` (в отличие от `/newevent`)

`/editevent` умеет **и понижать, и повышать** лимит, с разным поведением:

- **Понижение ниже текущего headcount** (сумма going+гости хаба и всех дочерних чатов с `status='going'`) → **отклоняется целиком**, лимит остаётся прежним, показывается сообщение с текущим headcount. Никакие другие поля из той же команды **тоже не применяются** (см. T13 в спеке `-wl`).
- **Повышение** → освободившиеся слоты автоматически заполняются из Waitlist в порядке FIFO (по `timestamp`, глобально по всем чатам сразу, не по одному чату за раз):
  - Для человека (не гостевой слот) — переносится в Going соответствующего чата (хаба или дочернего через `event_users`).
  - Для гостевого слота — сначала проверяется, что владелец слота **всё ещё** Going; если нет — слот просто отбрасывается **без** траты одного из освободившихся мест, поиск продолжается со следующей записи очереди.
  - Каждому продвинутому отправляется персональное уведомление в его чат.

### Синхронизация с Google Sheets

При изменении **имени** или **даты** — обновляются соответствующие ячейки (`B` — имя, `E` — дата) в строке события во вкладке `Events` (только если Sheet настроен). Остальные поля (иконки, лимит, видимость) в Sheets **не синхронизируются**.

### Тест-сценарии `/editevent`

- [ ] **E1.** Нет активного события → ошибка, ничего не меняется.
- [ ] **E2.** `/editevent` без аргументов → ошибка синтаксиса.
- [ ] **E3.** `/editevent NewName` → название меняется, остальное (иконки, дата, лимит) без изменений.
- [ ] **E4.** `/editevent -limit 5` при текущем headcount 8 → отклоняется, лимит остаётся прежним, показан текущий headcount (8).
- [ ] **E5.** `/editevent -limit 5 -ngl hidden` при headcount 8 → **обе** правки отклоняются (лимит и notgoinglist), так как вся команда прерывается до финального `UPDATE`.
- [ ] **E6.** Лимит поднят с 10 до 15 при 3 ожидающих в очереди (все — одиночные Going) → все 3 продвигаются, каждому приходит уведомление, Waitlist пустеет.
- [ ] **E7.** То же, но у первого в очереди гостевой слот, а владелец уже нажал Not Going → слот отбрасывается без уведомления и без траты свободного места, следующий по очереди получает это же место.
- [ ] **E8.** Одновременное изменение имени и даты, Sheet настроен → в Events-таблице обновляются обе соответствующие ячейки.
- [ ] **E9.** Изменение только иконки (`-gi`) → в Google Sheets **ничего** не обновляется (иконки не входят в синхронизацию).
