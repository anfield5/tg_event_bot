# Флаг: `-clc` / `-clickability`

**Используется в:** [`/newevent`, `/editevent`](../commands/newevent_editevent.md), [`/shareevent`](../commands/shareevent.md) (там — как per-share override, см. ниже)
**Синтаксис:** `-clc on|off` (или `-clickability ...`)
**Тариф:** требует PRO (фича `clickability`) — без него флаг отклоняется с ошибкой
**Дефолт:** `on`, если флаг не указан ни на уровне события, ни на уровне конкретного шаринга

---

## Назначение

Управляет тем, являются ли имена в посте кликабельными Telegram-упоминаниями (`tg://user?id=...`) или обычным текстом.

## Детальное поведение

1. **`on`** (дефолт) — каждое имя, для которого удалось разрешить `user_id`, рендерится как кликабельное упоминание.
2. **`off`** — все имена рендерятся как обычный escaped-текст, даже если `user_id` известен.

### Важный нюанс — не гарантирует 100% покрытие

`-clc on` означает **"делать ссылку там, где это физически возможно"**, а не "гарантированно у всех будет ссылка". Если у конкретного человека нет разрешённого `user_id` в базе (например, добавлен через Add Extra Member без резолва, или никогда не взаимодействовал с ботом и не является админом) — он **всегда** отображается обычным текстом, независимо от значения флага. Это ограничение Telegram Bot API, не баг: нет метода получить ID произвольного пользователя по username без его личного участия.

## На уровне `/shareevent` — per-share override

В `/shareevent` флаг `-clc` задаёт override **только для конкретного расшаренного чата**, а не для всего события:
- Если не указан → чат наследует значение `-clc` самого события.
- Если указан → **этот конкретный** чат использует своё значение, независимо от настройки события (может быть даже противоположным).

## Взаимодействие с другими флагами

- Не зависит от `-wl`/`-ngl` — применяется одинаково и к Going, и к Not Going, и к Waitlist спискам.
- В master-хабе кросс-чатовые записи ("Going from <chat>") используют кликабельность **своего исходного чата**, не хаба, в котором отображается пост.

## Тест-сценарии

- [ ] **T1 — Дефолт.** `/newevent Party` без `-clc` → `clickability = 'on'`.
- [ ] **T2 — Явный выбор.** `/newevent Party -clc off` → `clickability = 'off'`.
- [ ] **T3 — Гейтинг на FREE.** FREE-хаб, `-clc off` → ошибка "requires a higher tier", изменение не применяется.
- [ ] **T4 — Рендер `off`.** Есть человек с валидным `user_id` в Going → при `clickability=off` его имя рендерится **без** ссылки (обычный escaped-текст).
- [ ] **T5 — Рендер `on`, но без ID.** Человек добавлен через Add Extra Member без резолва ID, `clickability=on` → имя всё равно рендерится **без** ссылки (нет данных для ссылки, это ожидаемо, не баг).
- [ ] **T6 — Частичная кликабельность в одном посте.** Два человека в одном Going-списке: у одного есть `user_id`, у другого нет → первый кликабелен, второй — обычный текст, **оба** с `clickability=on`. Это корректное поведение, не рассинхрон.
- [ ] **T7 — Per-share override, chat=off при событии on.** Событие с `clickability=on`, конкретный шаринг с `-clc off` → **только этот** дочерний чат показывает всех обычным текстом, остальные (и хаб) — как обычно, кликабельно.
- [ ] **T8 — Per-share override отсутствует.** Шаринг без `-clc` → наследует значение события.
- [ ] **T9 — Обновление через `/editevent`.** Событие открыто с `clickability=on`, есть посты → `/editevent -clc off` → все посты (хаб + дочерние без своего override) перерендериваются с обычным текстом вместо ссылок.
